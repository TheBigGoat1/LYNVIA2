## A. Initial Setup & Installation

1. Open a terminal in the `lynviadigital-main` folder.
2. Install dependencies:
   ```bash
   npm install
   ```
3. Create a `.env.local` file (never commit this). Required keys:
   ```
   FIREBASE_PROJECT_ID=lynviadigital
   FIREBASE_SERVICE_ACCOUNT_JSON={"type":"service_account",...}
   GEMINI_API_KEY=your-gemini-key
   STRIPE_SECRET_KEY=sk_test_...
   NEXT_PUBLIC_STRIPE_PUBLISHABLE_KEY=pk_test_...
   NEXT_PUBLIC_PRIMARY_FIDUCIARY_COMPANY_ID=your-fiduciary-company-doc-id
   ```
4. Make sure your Firebase project has **Authentication** (Email/Password) and **Firestore** enabled.
5. Start the development server:
   ```bash
   npm run dev
   ```
6. Open the app at `http://localhost:9002`.

## B. Admin — First Login & System Preparation

1. Create the admin account (run once):
   ```bash
   npm run admin:create -- --email=admin@yourdomain.com --password=StrongPass123! --firstName=Admin --lastName=Owner
   ```
2. Open the app and log in with these credentials.
3. You land on the **Admin Dashboard** which shows:
   - Total users, companies, pending approvals, approved fiduciaries
   - Trend charts
   - List of pending user approvals and recent registrations
4. From here you can:
   - **Approve or reject** new accounting firm registrations
   - **Create users and companies** for business clients
   - **Review and approve documents** generated by individuals

---

## C. Admin — Upload Legal Database & Index for AI

1. While logged in as admin, go to **Legal Database**.
2. Click **Upload** and add your legal PDF documents (Swiss work laws, cantonal regulations, collective conventions, etc.).
3. Wait for each file to show status **Indexed / Ready**.
4. Open **RAG Playground**.
5. Ask 2–3 test questions, e.g.:
   - "What is the minimum vacation entitlement under Swiss CO?"
   - "What are the rules for maternity leave in Geneva?"
6. Verify that AI answers include **source citations** pointing to your uploaded documents.

> This legal database is what powers the AI Legal Assistant across all roles.

---

## D. Admin — Create Business Users & Companies

Business users cannot self-register through the public form. The admin must provision them.

1. Go to **Admin → User Management**.
2. Click **Create User**. Fill in:
   - Email, password, first name, last name
   - Role: `business`
3. Go to **Admin → Company Management**.
4. Click **Create Company**. Fill in:
   - Company name, type: `business`
   - Assign the **admin user** of that company (the user you just created)
   - Link the company to an accounting firm via `accountingFirmId` (must be a valid accounting firm company ID)
5. The business user's Firestore record must have `companyId` pointing to this company.
6. The business user can now log in and access the Business area.

---

## E. Admin — Document Approval Workflow

When individuals generate documents via AI, they arrive in the admin approval queue.

1. Go to **Admin → Document Approvals**.
2. You see all documents with status **Pending Review**.
3. Click on a document to preview it.
4. Choose:
   - **Approve** → status changes to "Approved", individual is notified
   - **Reject** → status changes to "Rejected", individual is notified
5. Approved documents become available for the individual to download as PDF/Word.
6. All actions are logged in the `system_logs` Firestore collection.

## I. Individual — AI Legal Assistant

**Path:** `/individual/legal-assistant`

1. Open the Legal Assistant page.
2. Type a question in natural language, e.g.:
   - "Can my employer reduce my salary without consent?"
   - "What are my rights if I am dismissed during probation?"

## J. Individual — AI Document Generator

**Path:** `/individual/document-generator`

1. Open the Document Generator.
2. **Step 1 — Choose a category:**
   - Assurance Maladie (health insurance letters)
   - Résiliation (termination notices)
   - Protection des Données (data protection requests)
   - Poursuites & Recouvrement (debt collection)
   - Transport Aérien (airline complaints)
   - Bail (lease disputes)
   - …and many more (200+ templates)
3. **Step 2 — Select a specific template** within the category.
4. **Step 3 — Fill in the form fields** (your name, address, dates, etc.). Your profile data is pre-filled when available.
5. **Step 4 — AI generates the document** in formal Swiss French style.
6. Review the preview. You can edit or regenerate.
7. Click **Submit**. The document is saved to Firestore with status `Pending Review`.
8. The admin reviews and approves/rejects it (see section E).
9. Once approved, you can download it as **PDF or Word** from My Documents.

## L. Individual — Financial Scenario Calculator

**Path:** `/individual/scenario-calculator`

This is the core financial planning tool. It uses the **real Swiss ESTV Tax API** (not mocked).

1. Open the Scenario Calculator.
2. Choose a scenario type:

| Scenario | What it answers |
|---|---|
| **Income Change** | "If my salary changes, how does my net income change?" |
| **Job Loss** | "What happens financially if I lose my job?" |
| **Child Birth** | "What benefits/allowances do I get with a new child?" |
| **Marriage** | "How does marriage affect my taxes and net income?" |
| **Pillar 3a** | "How much do I save with a Pillar 3a contribution?" (unlimited free) |
| **Pillar 2 Buyback** | "What's the tax impact of a pension fund buyback?" (unlimited free) |

3. Fill in the form: current salary, canton, municipality, marital status, number of children, church membership, etc.
4. Click **Calculate**.
5. The system calls the ESTV API and computes:
   - **Current situation** — federal tax, cantonal tax, municipal tax, church tax, social deductions (AHV, ALV, BVG, NBUV)
   - **Future situation** — same breakdown with your new parameters
   - **Net impact** — difference in net income
6. **AI Analysis** then interprets the results:
   - Plain-language summary
   - Actionable recommendations
   - Short-term and long-term financial impacts
7. Canton-based **health insurance subsidies** are automatically applied across all scenarios.
8. Results are saved to Firestore under `users/{uid}/scenarios/`.
9. You can view past scenarios from your history.

**Usage limits:**
- 2 free non-Pillar scenarios per month
- Pillar 3a and Pillar 2 Buyback: unlimited
- Buy more via Purchase Services (CHF 49 per add-on)

2. Click **Add Employee**.
3. Fill in the form:

## P. Business — Payroll Processing

**Path:** `/business/payroll-processing`

1. Open Payroll Processing.
2. You see all employees listed with their salary details.
3. For each employee the system calculates the **full employer cost breakdown**:

| Contribution | Default Rate |
|---|---|
| AHV/AVS (employer share) | 5.30% |
| Unemployment insurance (AC) | 1.10% |
| Accident insurance (LAA) | 1.50% |
| Daily sickness benefit (IJM) | 2.10% |
| Pension fund (LPP/BVG) | 3.50% (varies by age) |
| Family allowance (CAF) | 0.171% |

4. You can **adjust company-specific contribution rates** using the settings panel.
5. Both **hourly** and **monthly** employees are supported.
6. The page shows:
   - Per-employee cost breakdown
   - Company-wide salary total
   - Total employer contributions
7. Your accounting firm processes the actual payroll and sends you the documents through the Document Center (you receive a notification).

## Q. Business — Document Center (Exchange & History)

**Path:** `/business/document-center`

This is the hub for all document exchange between you and your accounting firm.

### Transmit Documents to Lynvia
1. Click **Upload New Document**.
2. In the dialog:
   - Select **document type**: bank statement, invoice issued, invoice paid (private/company), salary slip, VAT statement, vehicle contract, other
   - Enter **period** (e.g., "January 2025", "Q4 2024")
   - Add an optional **comment**
   - Drag & drop or choose files to attach
3. Click **Submit**. The document is sent to your accounting firm.

### Track Transmitted Documents
- The **Transmitted Documents** table shows every document you've sent:
  - Type, period, send date, status
  - Status colors: Pending (gray), Received (blue), Processing (yellow), Integrated into CFO (green), Missing (red), VAT Late (orange)
- When your accounting firm integrates a document into Virtual CFO analysis, it shows a green "CFO Source" badge.

### All Company Documents (from Firebase)
- The bottom table shows **all documents** across your company:
  - Documents generated by AI, transmitted docs, documents from your accounting firm
  - Searchable by name
  - Status: Approved, Pending Review, Draft, Rejected, Sent
  - Actions: View, Download, Share, Delete, Request Approval, Mark as Sent

## U. Business — Virtual CFO

**Path:** `/business/virtual-cfo`

1. Open Virtual CFO.
2. Enter your **monthly accounting numbers**:
   - Turnover (revenue)
   - Purchases
   - Raw wages
   - Salary expenses
   - Operating costs
   - Financial charges
   - Other charges
3. Click **Analyze**.
4. The system calculates:
   - **Profit/Loss** (turnover minus all charges)
   - **Key ratios**: Gross margin %, Wage-to-turnover %, Operating ratio %, Net margin %
5. **AI Financial Analysis** provides:
   - Executive summary of your financial health
   - Risk identification (low margin, negative result, etc.)
   - Cost optimization opportunities
   - Actionable recommendations
6. **Auto-generated alerts** appear if:
   - Gross margin falls below 20%
   - Profitability drops below 5%
   - Result is negative
7. A **6-month trend chart** shows how your numbers evolve over time.
8. Data is saved to Firestore under `companies/{companyId}/cfo_summaries/`.

> Your clients (business users) can see these analyses once you enter the numbers.

## Z. Production Build & Deployment

### Pre-deployment checklist

Before going live, verify:

- [ ] `.env` / `.env.local` files are **NOT committed to git** (rotate all keys if they were)
- [ ] Firestore security rules are deployed (restrict read/write by role)
- [ ] Admin layout has a role guard (only `role === 'admin'` can access)
- [ ] `/api/checkout_sessions` validates Firebase auth token
- [ ] Individual layout checks for authenticated user
- [ ] All Stripe keys are switched from `sk_test_` / `pk_test_` to live keys
- [ ] ESTV Tax API is accessible from your production server
- [ ] Gemini API key has production quota

### Build

```bash
npm run build
```

Fix any TypeScript errors that appear. Then:

```bash
npm run start
```

The app runs at `http://localhost:3000` (production mode).

### Deploy to hosting

For **Vercel** (recommended for Next.js):
1. Push your code to GitHub (without `.env` files).
2. Connect the repo to Vercel.
3. Add all environment variables in Vercel dashboard → Settings → Environment Variables.
4. Deploy.

For **Firebase Hosting** or other platforms, follow their respective Next.js deployment guides.

### Post-deployment smoke test

1. Register a new individual account → confirm login works.
2. Run one scenario calculation → confirm ESTV API responds.
3. Generate one document → confirm AI generation works.
4. Log in as admin → confirm document approval works.
5. Log in as accounting firm → confirm subscription checkout works.
6. Switch locale (FR/EN/DE) → confirm translations load.

## Troubleshooting

| Problem | Solution |
|---|---|
| "Access Restricted" on Business pages | Ensure user has `role: business`, a valid `companyId`, and the company exists in Firestore |
| Scenario calculator returns no results | Check that ESTV API is reachable; verify canton/municipality codes are valid |
| AI Legal Assistant gives generic answers | Upload and index legal documents in Admin → Legal Database |
| Stripe checkout fails | Verify `STRIPE_SECRET_KEY` and `NEXT_PUBLIC_STRIPE_PUBLISHABLE_KEY` are set correctly |
| Accounting Firm sees "Upgrade Required" | User is on Basic tier; the feature requires Pro or Advanced subscription |
| Documents stuck in "Pending Review" | Admin must approve them in Admin → Document Approvals |
| Employee payroll shows wrong deductions | Check and adjust company-specific contribution rates in Payroll Processing settings |
| Profile completion screen won't go away | Business/Accounting Firm users must fill all required company profile fields |
